# Voxint security audit -- 2026-09-20

> Delta security audit covering v0.38 through v0.44.0 (~80 first-parent commits
> since the [2026-08-18 audit](audit-2026-08-18.md) at `main` @ `139ebe3`).
> **Report only**: no code was changed. Findings are ranked by *real-world
> exploitability for Voxint's actual audience*, not by generic CVSS.
>
> This audit was conducted at `feat/119-rocm-fingerprint-probe` @ `f4b5716`.

## Threat model (updated calibration lens)

The original audit's single-operator model has expanded. Three changes shift the
boundary:

1. **Multi-user mode** with roles (admin, reviewer, viewer) is now available.
   This introduces a real authorization boundary: a viewer or reviewer should not
   be able to reach admin-only mutations, see other users' data without
   authorization, or escalate privileges.
2. **Docker socket service controls** (opt-in compose overlay) grant the API
   container host-equivalent Docker authority when enabled.
3. **BYO LLM endpoints** create operator-configured outbound connections that
   carry API keys and transcript content.
4. **demo.voxint.app** is a publicly reachable multi-user instance. Journalists
   face sophisticated adversaries; RCE-capable surface is not discounted just
   because the default deployment is loopback.

The exclusions from the original audit still hold: multi-tenancy, DDoS,
horizontal scale, SSO, and formal compliance frameworks remain out of scope.

## Method

Six bounded Codex (GPT-5-family) review packages dispatched in two parallel
waves, each targeting a specific trust boundary. Automated tooling (pip-audit,
trivy, bandit, npm audit, gitleaks) provided a scanner baseline. Live Playwright
testing probed the demo site. A 5-voice pre-audit consult (Codex, DeepSeek V4
Pro, Grok 4.5, GLM 5.2, Kimi K3) set scope and priorities.

| Subsystem | Reviewer | Validation |
|---|---|---|
| Auth, sessions, roles, CSRF, Docker socket | Codex (Package A) | 158 targeted tests passed; 117 routes inventoried |
| Uploads, media processing, M1/M2 | Codex (Package B) | 139 focused tests; ffmpeg reproductions in disposable containers |
| BYO LLM, research/enrichment, E3-E6 | Codex (Package C) | 252 targeted tests; ASGI probes for authorization and redirects |
| Restart-from-stage pipeline mutation | Codex (Package D) | 70 unit tests; code-inspection concurrency analysis |
| SSE, frontend rendering, speaker assignment | Codex (Package E) | 46 Python + 82 Vitest tests; ASGI connection probes |
| Supply chain, Deno, ROCm probe, F5 | Codex (Package F) | Targeted pytest runs; Dockerfile and workflow inspection |

Cross-package checks: A+E (viewer-to-admin XSS chains), B+C (outbound media
access via enrichment), A+F (Docker socket privilege + supply chain).

## Overall posture

The load-bearing defenses identified in the 2026-08-18 audit remain intact and
correct:

- **Model-weight integrity** is still excellent (sha256-verified, contract-tested,
  immutable release assets).
- **SSRF on the research path** remains closed (verified: DNS rebind, redirect,
  IP-encoding all defeated).
- **Path confinement** is consistent (`resolve()` + `is_relative_to` everywhere).
- **yt-dlp lockdown** is thorough (no config/plugin/exec, proxy pinned,
  group-kill, redacted logs).
- **Web console rendering** is safe: no `|safe`, no `Markup(untrusted)`, no
  `dangerouslySetInnerHTML` or `innerHTML` in production code. Jinja2
  autoescaping is on throughout.
- **Session management** is solid: 32-byte random tokens, SHA-256 hashed storage,
  expiry enforced, revocation on password/role change, last-admin row locking
  with `SELECT ... FOR UPDATE`.
- **No SQL injection**: all user input flows through SQLAlchemy ORM or safe
  Postgres functions (`websearch_to_tsquery`).
- **Docker service allowlist** is tight: only `transcription`, `diarization`,
  `speaker_embedding` accepted; admin-gated; CSRF-protected.
- **All 107 console write routes** correctly reject viewer access with 403.
- **Deno** is version-pinned with per-architecture SHA-256 checks and restricted
  runtime (`--no-remote`, `--no-config`, no `--allow-all`).
- **ROCm probe** reads sysfs directly (no subprocess shell-out, no privileged
  device access).
- **Command palette** is filtered server-side by role.

**No Critical findings. No confirmed unauthenticated remote code execution.**
The highest-severity issue is a reviewer-to-admin configuration bypass that
enables LLM API key theft.

## Findings

Severity key (calibrated to this audience): **High** = realistically exploitable
or data-loss with little operator error; **Medium** = real, needs a precondition
or is bounded; **Low** = hardening, defense-in-depth.

### N1 -- High -- setup wizard bypasses admin-only configuration

- **Where:** `src/voxint/api/routers/settings.py:154` (`setup_router`), `:1868`,
  `:1897` (`setup_llm`).
- **Defect:** `setup_router` requires write access but not admin access. Its
  handlers remain available after onboarding completes. All six setup POST
  routes (`/setup/scan`, `/setup/scan/confirm`, `/setup/folders`,
  `/setup/vocabulary`, `/setup/llm`, `/setup/finish`) have CSRF and viewer
  protection but lack the stronger admin gate that their `/settings/*`
  equivalents enforce.
- **Scenario:** A reviewer obtains a `CSRF_SETUP` token through `/setup`, changes
  the LLM endpoint to an attacker-controlled server, and leaves the API key
  field blank. The saved key (or environment fallback) is retained. Subsequent
  LLM requests send the existing bearer credential and transcript content to the
  attacker. The attacker also controls resulting model output.
- **Cross-validation:** Independently discovered by Codex Packages A and C.
  Package A confirmed with a stubbed-persistence probe: reviewer `/setup/vocabulary`
  returned 303 and changed the row; reviewer `/settings/glossary` returned 403.
  Package C confirmed the same for `/setup/llm`.
- **Fix:** Add `_require_admin` to the entire `setup_router`. Bind credentials to
  their endpoint origin and require explicit credential reassignment when that
  origin changes. Consider rejecting setup mutations after onboarding.

### N2 -- High (conditional) -- Docker socket mount permits host escalation

- **Where:** `compose.service-controls.yaml:19`, socket mount and supplementary
  group.
- **Defect:** The opt-in overlay grants direct Docker socket access to the API
  container. Application-level allowlists constrain normal requests to three
  named services, but a compromised API process has unrestricted access to the
  Docker Engine API: container creation, exec, deletion, and host bind mounts.
- **Scenario:** An attacker who achieves code execution in the API process (via a
  dependency, a deserialization bug, or a future vulnerability) escalates to the
  host through the Docker socket.
- **Calibration:** This is a documented, opt-in architectural risk. The restart
  endpoint's allowlist, admin gating, and CSRF are correct and were verified.
  The finding is **conditional** on both the overlay being enabled and a separate
  code-execution primitive.
- **Fix:** Replace the direct socket mount with a narrowly constrained
  broker/proxy that permits only inspection and restart of explicitly approved
  containers.

### N3 -- High -- unauthenticated uploads consume disk before authentication

- **Where:** `src/voxint/api/routers/media.py:582` (`media_submit_upload`),
  `src/voxint/api/app.py:465` (request-size middleware),
  `src/voxint/config.py:148`.
- **Defect:** Multipart parsing spools uploads to temporary storage before
  `OperatorDep` authenticates. The default limit is 5 GiB per file. There is no
  aggregate in-flight byte budget or server-side upload concurrency limit.
- **Scenario:** An unauthenticated attacker sends concurrent multipart requests.
  Each consumes temporary storage and disk I/O before the 401 is returned.
- **Reproduction:** A 2 MiB upload was confirmed spooled to disk before returning
  401.
- **Calibration:** The default bind is `127.0.0.1`, so exploitation requires the
  operator to have exposed the port or placed a reverse proxy that forwards
  unauthenticated bodies. On loopback without a proxy, this is self-inflicted.
- **Fix:** Authenticate upload requests before multipart parsing. Enforce
  aggregate in-flight storage and concurrency budgets. Add body-read deadlines
  before spooling.

### N4 -- High -- restart deletes operator corrections without acknowledgment

- **Where:** `src/voxint/ingest/service.py:1100` (`restart_impact`), `:1317`
  (segment deletion), `src/voxint/db/models.py:1415` (`ON DELETE CASCADE`).
- **Defect:** Restarting from acquire, prepare, or transcribe passes the impact
  gate and permanently deletes `SegmentReviewState`, including text corrections
  and verification marks. The impact calculation never counts these records.
  Other segment-linked editorial data also cascades.
- **Scenario:** A reviewer or admin restarts a terminal run that has verified
  segments and corrected text. The acknowledgment dialog shows zero affected
  decisions because corrections are not counted. The editorial work is
  permanently lost.
- **Fix:** Include corrections, verification marks, and other affected editorial
  records in the impact preview and acknowledgment gate. Preserve their
  provenance before deleting segments.

### N5 -- High -- SSE connections can exhaust the database pool

- **Where:** `src/voxint/api/routers/activity.py:75` (`activity_stream`),
  `src/voxint/api/routers/deps.py:166` (`_get_session`).
- **Defect:** Each open SSE stream retains the authentication/onboarding database
  connection for its lifetime. Polling requires another connection. There is no
  per-user or global stream limit.
- **Scenario:** An authenticated account (including a viewer) opens enough
  concurrent SSE connections to exhaust the database pool. Other console requests
  fail.
- **Reproduction:** A targeted ASGI probe confirmed one connection checked out
  during idle streaming, zero after disconnect.
- **Fix:** Finish authentication and onboarding transactions before entering the
  streaming loop. Add per-user and global connection limits with cleanup in
  `finally`. Preserve short-lived polling sessions.

### N6 -- Medium -- M1 confirmed: nested media inputs bypass path confinement

- **Where:** `src/voxint/media/normalize.py:52` (`probe_audio`), `:104`
  (ffmpeg invocation).
- **Defect:** Neither invocation restricts input demuxers or sets a protocol
  whitelist (`-protocol_whitelist`). ffmpeg lacks `-nostdin`. The existing `-f wav`
  specifies the *output*, not input.
- **Scenario:** An uploaded `.m3u8` references an absolute AAC path outside its
  directory and incorporates that audio into the normalized output. A `.wav`
  containing ffconcat also loads relative sibling media.
- **Reproduction:** Confirmed in the v0.43 image (FFmpeg 7.1.5-0+deb13u1). HTTP
  references were blocked by default protocol whitelist; absolute local file
  references were not. Unrestricted SSRF was **not** demonstrated.
- **Prior finding:** M1 from the 2026-08-18 audit. Still unpatched.
- **Fix:** Allowlist supported self-contained input demuxers; reject
  playlist/reference formats. Explicitly restrict protocols and disable ffmpeg
  stdin. Sandbox decoding with access only to the submitted input and output
  directory. Note: `-protocol_whitelist file,crypto,data` alone does not confine
  filesystem reads.

### N7 -- Medium -- M2 confirmed: PREPARE has no timeout or decoded-output cap

- **Where:** `src/voxint/media/normalize.py:34` (default timeout), `:104`
  (normalization), `:127` (output probe).
- **Defect:** PREPARE supplies no subprocess timeout, `-fs`, or `-t`. Its output
  probe is also unbounded. `capture_output=True` accumulates stderr before
  truncation.
- **Scenario:** A 1,421-byte playlist referencing a one-second WAV 100 times
  produced 3,200,078 bytes of output. Normalized PCM consumes roughly
  115 MB per audio hour; thousands of decoded hours can consume hundreds of GB.
- **Prior finding:** M2 from the 2026-08-18 audit. Still unpatched.
- **Fix:** Enforce decoding/probe deadlines, decoded-byte and duration ceilings,
  and bounded stderr capture. Treat ceiling violations as failures. Move
  subprocess execution inside the cleanup `try/finally` so timeout exceptions
  also remove temporary output.

### N8 -- Medium -- LLM endpoint allows link-local and metadata SSRF

- **Where:** `src/voxint/api/setup_wizard.py:184` (`normalize_llm_base_url`),
  `src/voxint/clients/llm.py:198` (`httpx.Client`).
- **Defect:** Neither URL validation nor connection establishment rejects
  link-local destinations. `netcheck.ip_is_public` is not applied. DNS results
  are not checked, and resolved addresses are not pinned.
  `http://169.254.169.254/v1` passes validation.
- **Scenario:** An attacker with endpoint-configuration access (including via N1
  reviewer bypass) points the LLM endpoint at a cloud metadata service.
- **Calibration:** RFC1918 addresses *must* remain allowed for local LLM
  deployments (Ollama on a LAN box). Applying the public-only ingest policy
  unchanged would break legitimate use.
- **Fix:** Introduce a dedicated LLM destination policy that preserves RFC1918
  and local LLM access, blocks link-local and metadata destinations (including
  embedded address forms), and checks/pins DNS results at connection time.

### N9 -- Medium -- LLM responses have no transport-level size or duration bound

- **Where:** `src/voxint/clients/llm.py:200` (timeouts), `:292` (`post`),
  `:303` (content-length check).
- **Defect:** HTTPX buffers the entire response and JSON parsing occurs before
  the completion-content limit. Enhancement and error responses are also
  buffered. Read timeouts constrain inactivity, not total elapsed time.
- **Reproduction:** A 2 MiB response with irrelevant envelope padding and
  completion content `{}` was accepted.
- **Fix:** Stream responses under a decoded-byte ceiling and absolute deadline.
  Enforce these limits for both successful and error responses before JSON
  parsing.

### N10 -- Medium -- login has no application-level rate limiting

- **Where:** `src/voxint/api/routers/auth_pages.py:109` (`authenticate(...)`).
- **Defect:** Login attempts have no throttling, backoff, or concurrency cap.
  Publicly obtainable CSRF tokens do not restrict automated attempts.
- **Scenario:** An attacker with network access to `/login` attempts brute-force
  password guessing. Concurrent Argon2 verification also creates a resource
  exhaustion vector.
- **Calibration:** On loopback single-operator mode, this is Low. In multi-user
  mode behind a reverse proxy or on the demo instance, this is Medium.
- **Fix:** Add shared per-account and per-source throttling, bounded verification
  concurrency, and progressive backoff. Avoid attacker-triggered permanent
  lockout.

### N11 -- Medium -- concurrent review decisions can bypass restart acknowledgment

- **Where:** `src/voxint/ingest/service.py:1497` (unlocked read), `:1318`
  (`_void_run_decisions`), `src/voxint/adjudication/slots.py:84`
  (`verify_claim`).
- **Defect:** Restart checks impact without locking the run. A reviewer can
  commit a decision between the impact check and invalidation. Review decisions
  do not increment the pipeline revision, so the final CAS does not detect this
  race. Early-stage invalidation can subsequently revoke that decision without
  `acknowledge_void`.
- **Fix:** Acquire and refresh the run with `SELECT ... FOR UPDATE` before
  reading status or calculating impact. Use the same lock as review mutations.
  Hold it through invalidation and transition.

### N12 -- Medium -- historical stage completions authorize restarts after outputs invalidated

- **Where:** `src/voxint/ingest/service.py:1382` (`upstream_completed`),
  `src/voxint/pipeline/stages/finalize.py:15`.
- **Defect:** Prerequisite checks accept any historical successful upstream
  attempt. A restart from an early stage that deletes the transcript, then fails
  before replacing it, leaves a subsequent restart from `finalize` able to
  complete with a missing transcript.
- **Fix:** Track which stage outputs remain valid across restart boundaries and
  validate those outputs. Merely requiring the current cycle would incorrectly
  reject legitimately preserved upstream outputs.

### N13 -- Medium -- SSE streams survive session revocation

- **Where:** `src/voxint/api/routers/activity.py:104` (unbounded stream loop),
  `src/voxint/api/auth.py:68` (`load_session_user`).
- **Defect:** Authentication is checked only at connection time. Existing streams
  continue receiving activity events after session expiry, logout, password
  reset, or account disablement. Events include speaker names, media titles, and
  activity metadata.
- **Fix:** Periodically revalidate the session and account using a short-lived
  transaction. Terminate invalid streams. A bounded stream lifetime requiring
  reauthentication can supplement this.

### N14 -- Medium -- model-service Python dependencies are not hash-locked

- **Where:** `services/whisper/Dockerfile:25`, `services/pyannote/Dockerfile:36`,
  `services/synthdetect/Dockerfile:37`.
- **Defect:** Top-level version pins leave transitive dependencies and build tools
  floating. No hash verification. The synthdetect service uses an abbreviated
  Git commit revision for Fairseq.
- **Fix:** Commit complete, per-platform dependency locks with hashes. Enforce
  hash checking and pin build tools. Replace abbreviated Git revisions with full
  commits.

### N15 -- Medium -- most image inputs use mutable tags

- **Where:** `Dockerfile:4` (`node:22-slim`), `:13` (`python:3.12-slim`), `:43`
  (`uv:0.8`), `compose.yaml:18` (`pgvector:pg17`).
- **Defect:** Base images use floating version tags. CUDA/ROCm bases and Redis
  also use tags.
- **Calibration:** The llama-cpp Dockerfile already pins by digest, showing the
  pattern.
- **Fix:** Pin external image references by digest with automated reviewed
  updates.

### N16 -- Low -- login CSRF tokens are not session-bound

- **Where:** `src/voxint/api/routers/auth_pages.py:40`, `:96`,
  `src/voxint/api/csrf.py:289`.
- **Defect:** The login token signs action, nonce, and timestamp but is not bound
  to a browser session. A token obtained by one client can be used by another.
  `SameSite=Lax` does not prevent this because no existing session cookie is
  required.
- **Scenario:** An attacker with valid Voxint credentials induces a victim to
  submit a cross-site login form, logging the victim into the attacker's account.
- **Fix:** Bind login CSRF to a browser-specific pre-session and validate request
  origin.

### N17 -- Low -- public API documentation bypasses authentication

- **Where:** `src/voxint/api/api_app.py:171` (built-in documentation
  configuration).
- **Defect:** `/api/v1/docs`, `/api/v1/openapi.json`, `/api/v1/redoc`, and
  `/api/v1/docs/oauth2-redirect` do not pass through `ApiKeyDep`. They return
  HTTP 200 without credentials.
- **Impact:** Unauthenticated disclosure of API structure and application
  version. No protected application data.
- **Fix:** Disable built-in documentation or provide explicitly authenticated
  replacement routes.

### N18 -- Low -- E3 still open: link grounding against known_urls is overly broad

- **Where:** `src/voxint/research/agent.py:410`, `:580`, `:699`.
- **Status:** Unchanged from the 2026-08-18 audit. `known_urls` includes every
  search-result URL, not just fetched pages. An SEO-poisoned result URL can
  acquire apparently grounded draft evidence.

### N19 -- Low -- E4 still open: egress proxy tunnels any public port

- **Where:** `src/voxint/media/egress_proxy.py:57`, `:258`.
- **Status:** Unchanged from the 2026-08-18 audit. The proxy binds `0.0.0.0:3128`
  and permits CONNECT to any valid port, including 25. The supplied Compose
  overlay publishes no host port, limiting exposure.

### N20 -- Low -- E6 still open: roster-only lookup can retire research drafts

- **Where:** `src/voxint/research/agent.py:638`, `:704`,
  `src/voxint/enrichment/drafts.py:653`.
- **Status:** Unchanged from the 2026-08-18 audit. An empty roster lookup
  satisfies the investigation gate and can supersede previous research drafts.

### N21 -- Low -- startup orphan cleanup follows incoming symlink

- **Where:** `src/voxint/ingest/service.py:2013`
  (`reconcile_orphaned_incoming`).
- **Defect:** Cleanup follows a symlink at `media_root/incoming`.
  `relative_to(media_root)` checks lexical paths without resolving them.
- **Scenario:** A local user replaces `incoming` with a symlink. On API startup,
  files outside `MEDIA_ROOT` are deleted if the service has deletion permission.
- **Calibration:** Requires local filesystem access. Browser upload alone cannot
  create this condition.
- **Fix:** Reject a symlinked `incoming`. Resolve and confine traversal roots.

### N22 -- Low -- F5 whisper checksum gap remains

- **Where:** `services/whisper/Dockerfile:33`, `Dockerfile.cpu:34`,
  `Dockerfile.rocm:76`.
- **Status:** HF-commit-revision-pinned but no repository-owned SHA-256 manifest
  covering model bytes. Theoretical: requires artifact-delivery compromise at the
  pinned revision.

### N23 -- Low -- F5 GHA cache trust remains theoretical

- **Where:** `.github/workflows/release.yml:132`, `:501`.
- **Status:** Release builds import `type=gha` caches. No PR-to-release
  cache-poisoning path was demonstrated through ordinary forks. `ci.yml` does
  not export these Docker caches. Image-specific scopes prevent collisions.

### N24 -- Low -- Dependabot covers only GitHub Actions

- **Where:** `.github/dependabot.yml:8`.
- **Defect:** Python and npm ecosystems are not covered by Dependabot. `npm
  audit` runs in CI but there is no configured automated update mechanism for
  either ecosystem.
- **Fix:** Add Dependabot or Renovate coverage for the root Python lock, service
  requirements, and frontend npm lock.

### N25 -- Low -- release signing and SBOM generation absent

- **Where:** `.github/workflows/release.yml:126`, `:658`.
- **Defect:** No explicit image signing or SBOM generation in the release
  workflow. Consumers lack a configured signature-verification path.
- **Calibration:** `docker/build-push-action` provides provenance attestation by
  default for registry exports. Actual published manifests were not inspected.
- **Fix:** Sign final published digests using a constrained release identity.
  Document verification. Enable `sbom: true`.

## Demo site observations (demo.voxint.app)

Tested via live Playwright browser automation and curl header inspection on
2026-09-20.

- **Version:** 0.45.0 (ahead of the audited 0.44.0 release image).
- **Unauthenticated access:** Only `/healthz` responds without credentials. All
  other paths redirect to `/login`.
- **API sub-app:** `/api/v1/docs` returns 404. The API sub-app may not be
  mounted in demo mode, or no API key is configured.
- **Headers present:** `Referrer-Policy: no-referrer` (app),
  `X-Content-Type-Options: nosniff` (app), `X-Frame-Options: SAMEORIGIN`
  (nginx), `Strict-Transport-Security: max-age=31536000; includeSubDomains`
  (nginx).
- **Headers absent:** `Content-Security-Policy`.
- **Duplicate headers:** `X-Content-Type-Options` appears twice (nginx repeats
  what the app sets). `Referrer-Policy` appears twice with conflicting values:
  `no-referrer` from the app and `strict-origin-when-cross-origin` from nginx.
  The browser applies the *last* value, which is the weaker nginx one.

### Header recommendations

- Deduplicate `X-Content-Type-Options` and `Referrer-Policy` in the nginx
  configuration (remove the nginx directives; the app already sets them
  correctly).
- Add a baseline `Content-Security-Policy: default-src 'self'; media-src blob:
  'self'; connect-src 'self'; style-src 'self' 'unsafe-inline'` in report-only
  mode, then tighten. This adds defense-in-depth against stored XSS from model
  output or transcript content.

## Verified non-findings (do not "fix" these)

- **No unsafe rendering sinks** in production code. No `|safe`, no
  `Markup(untrusted)`, no `dangerouslySetInnerHTML`, no `innerHTML` assignment.
  The two `Markup()` helpers (`runs_query.py:370`, `meaning_query.py:266`)
  escape input before inserting fixed `<mark>` tags.
- **All 107 console write routes** reject viewer access with 403. No
  method-override bypass found.
- **Docker service allowlist** accepts only 3 keys; admin-gated; CSRF-protected.
  Container IDs come from Docker responses, not user input.
- **Session management** uses 32-byte tokens, SHA-256 hashed storage, enforced
  expiry, and session revocation on password/role changes. Disabled accounts are
  rejected. Last-admin protection uses `SELECT ... FOR UPDATE`.
- **No SQL injection.** All user input flows through SQLAlchemy ORM or safe
  Postgres functions.
- **Path confinement** is consistent and correct across upload, serving, GPU
  service, and HTTP client paths.
- **yt-dlp lockdown** is thorough.
- **Deno** is version-pinned (2.9.7), per-architecture SHA-256 checksummed,
  runs with `--no-remote --no-config --no-prompt` and no `--allow-all`.
  Processes fetched YouTube player JavaScript inside a constrained sandbox.
- **ROCm probe** reads sysfs directly. No `rocm-smi` subprocess, no privileged
  device access, no PATH hijacking surface.
- **SSRF on research path** remains closed and verified.
- **Command palette** is filtered server-side by role; no admin-action exposure
  to viewers.
- **Progressive rendering** and **waveform selection** are client-side only; no
  server cursor/offset or time-range processing surface.
- **Speaker assignment popover** uses authenticated endpoints with claim-token
  CSRF resistance; viewers are denied.
- **YAML sidecar loader** (`sidecar.py:171`) subclasses `yaml.SafeLoader`;
  does not enable Python-object construction.
- **AMI XML parser** (`ami_recurrence.py:91`) receives input from an
  operator-selected offline corpus file via a CLI tool. No web or console path
  reaches it.

## Summary

This delta audit found **5 High, 10 Medium, and 10 Low** findings. The highest
severity is an authorization bypass in the setup wizard (N1) that lets a
reviewer steal the operator's LLM API key and redirect model requests. The two
media-processing findings from the 2026-08-18 audit (M1, M2) remain open and
were confirmed exploitable with reproductions.

The codebase's security posture remains strong. The core defenses (CSRF,
credential handling, path confinement, weight integrity, SSRF, rendering safety)
are intact and correct. The new findings cluster around three areas: the
multi-user authorization boundary (N1, N5, N10, N13, N16, N17), pipeline
mutation integrity (N4, N11, N12), and supply-chain hardening (N14, N15, N24,
N25).

### Recommended priority order

1. **N1** (setup wizard admin bypass) and **N8** (LLM metadata SSRF): fix
   together, as N1 is the primary path to N8.
2. **N4** (restart correction loss): the impact gate omission is a
   straightforward addition.
3. **N5** (SSE pool exhaustion): release the DB session before streaming.
4. **N6/N7** (M1/M2 ffmpeg hardening): implement input-demuxer restrictions and
   resource bounds.
5. **N3** (pre-auth upload spool): authenticate before parsing, or enforce
   aggregate budgets.
6. Everything else by severity tier.
